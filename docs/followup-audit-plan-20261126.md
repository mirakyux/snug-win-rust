## 驱动管道与日志重试修复

- 将单个请求的 JSON 负载限制为 512 KiB，足以容纳当前 16 个监视器、每屏 256 个模式、每模式 4 个刷新率以及最大名称的合法请求。上限按帧计算，结束符不计入负载；一个读取中合并多个合法帧时逐个处理，保留下一帧的半包。只扫描新读入的数据，拒绝超长负载前不再追加内存，不改变管道 DACL。
- 日志初始化失败后仍允许驱动启动。后台重试超过五分钟即退出，删除把 DriverEntry 的 PDRIVER_OBJECT 强转成 WDFDEVICE 的调用及跨线程指针捕获。依据微软 [WdfDeviceSetFailed 参数契约](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdfdevice/nf-wdfdevice-wdfdevicesetfailed)，该 API 只接受有效框架设备句柄；日志成功优先于同轮超时，成功后不额外等待。
- 先新增直接抽取生产帧缓冲与日志线程代码的隔离故障回归，再做红绿验证；覆盖无结束符持续输入、跨块超限、精确上限、最大合法请求、多帧合并与半包，以及持续日志失败超时和临界轮成功。固定 nightly 分别编译 Debug/Release，不运行真实驱动管道。
- 驱动文件版本升级为 0.4.0.7，新增源码修复标识。专项通过后交主线整合构建与 ABI/产物验收；本 lane 不签名或安装驱动。

## 共享恢复账本的跨屏保护

已用隔离回归确认：来源屏记录拒绝删除后，其他屏可提前消费共享交接记录并重复偿还字号；其他屏的自动归还也会误操作正在来源屏摆放的窗口。

由现有共享串行队列的 Hub 汇总活跃屏与退休屏的来源记录、待回写记录和当前摆放窗口，再向同组共享账本发布保护快照。自动消费、显式放置匹配和账本裁剪均遵守保护；任一来源暂时读不到时暂停消费。来源未结算的退休屏继续保留并重试，来源成功结算后解除保护。测试覆盖跨屏拒删与解锁重试、其他屏当前摆放、退休来源、同 ID 重建和读取失败，不引入通用事务或新依赖。

## 旧版无令牌归属的 V2 保护

已在隔离副本复现：旧版仅编号账本会在 V2 上删除其他 owner 复用的编号；仍存活的 Legacy 会话切换到 V2 后，也会无令牌替换外来显示的模式。先移植两条红灯，并增加真实 VddClient / 测试命名管道边界验证，再在 replace_legacy、remove 及 Legacy 写入失败重连路径拒绝 V2 无令牌操作。旧协议仍只报告提交，保留旧归属记录和现有会话绑定；不通过 State 快照猜测所有权，不扩充驱动协议、不引入依赖。专项覆盖协议切换、权限代理执行、旧记录不误销账和 Legacy 正常替换/删除。只使用隔离测试管道，不操作真实显示。

已登记的旧 helper 缺少这道 V2 保护，因此无令牌替换与删除使用新的 LegacyOnlyReplace / LegacyOnlyRemove 代理请求名，使旧 helper 在接触驱动前拒绝。新 helper 保持 Legacy 正常路径；不接受旧请求名别名、不改变驱动协议。先用紧邻旧版本的请求枚举复现兼容绕过，再验证新旧请求相互拒绝。

启动时同样恢复已删除配置的残留来源：首次发现仅枚举数据目录内精确匹配的 phone-screen.json 与 screen-<id>.json，跳过当前愿望/活跃 ID，以 wanted=false 的既有 core 进入退休恢复队列，绝不建屏。完整目录枚举成功后只登记一次；目录失败阻挡共享消费并由 recover/settle 重试，单个来源读失败保留 core；缺失目录视为空。新增启动复现、legacy、同 ID、目录与来源锁定回归。

最终复核补充：精确匹配的来源路径即便暂为目录或异常链接也不能跳过，交给原账本读取错误路径保留并重试；失败移交后原 WindowKey 再次可恢复时，在来源偿还字号前先持久撤回相同共享副本，撤回失败则保留来源并停止，以免来源 zoom 更新后旧副本失去相等保护而被重复消费。以上均先保存隔离红灯。

同一共享冗余撤回也放到 write_record 与影子回写入口，覆盖真实 placement 在失败移交后继续修改字号/filled 的路径。隔离红灯显示旧副本被提前偿还后总字号增量为 1（应为 3）。普通 symlink 因当前 Windows 权限无法创建；真实断 junction 回归验证读取失败保留，另以 symlink_metadata 在 NotFound 时防止仍存在的断链被当空。后者普通 symlink 路径未在本机实测，不声称红绿复现。
