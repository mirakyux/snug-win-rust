# 远控退出后仍显示在线

## 本机证据

用户反馈退出远控后，虚拟屏延迟撤销可以接受，但撤屏后仍显示在线。

本机日志确认本次生命周期已结束：

- 17:30:55：远程会话已断开，控制端 0 个。
- 17:31:10：重连窗口结束，开始撤屏并还原当前应用。
- 17:31:14：手机屏 #0 已撤除，撤屏结束。
- 此后没有重新连入或加屏。17:38:58 再次发生实体屏拓扑变化时，GUI 才记录移到屏外待命及关闭触控接管。

`DeskSet::set_wishes([])` 已从活跃集合移除旧 desk；后台快照随后为空，读取不存在的屏应返回 `Off`。托盘文案、在线图标和 GUI 侧钩子同步却都依赖 `App::update`，所以后台完成撤屏不能保证这些显示立即更新。

已安装的 egui 0.32.3 会合并尚未消费的重绘请求：一次请求将等待时间设为零后，未进入下一帧时，重复 `request_repaint()` 不再调用原生重绘回调。因此旧的 250 ms 心跳不能保证持续唤醒原生窗口。另有一次通知可能先于后台快照替换，使观察者短暂读到旧状态。

旧进程还出现单线程较高 CPU；结合后续实体屏变化才恢复的现象，不能排除原生渲染或驱动停顿。没有故障时的线程栈证据，不能断言具体卡在 OpenGL 哪个调用，也不能仅凭合并请求缺陷就解释全部真机现象。

## 修复

- `ui.rs` / `main.rs`：保留 250 ms 心跳，增加独立的原生重绘投递。启动时在 GUI 线程查找并缓存自己的窗口，后台不再同步读取本进程窗口标题，避免退出等待心跳线程时形成互等。
- `snug-win/window.rs` / `lib.rs`：验证窗口仍属于本进程后异步投递 `WM_PAINT`。已核对 winit 0.30.13 会将其派发为 `RedrawRequested`；不改焦点、窗口位置或显示模式。
- `controller.rs`：新快照写入并释放锁后才通知界面，未变化时不重复通知。
- `controller.rs`：没有任何就绪屏时，后台主动停用触控接管，清除直通区域与安装缓存；即使没有 GUI 帧，旧钩子也不会继续接管，重连同一矩形时能重新安装。
- 同步 CHANGELOG 和验收清单。

复用原有心跳、快照和输入钩子，没有新增依赖或后台服务，没有更改断开防抖与重连等待策略。
