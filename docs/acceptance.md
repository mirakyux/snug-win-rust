# Windows 真机与更新验收

先退出正在运行的旧进程。数据目录设置为 `SNUGWIN_HOME` 的隔离实例不会迁移或修改全局自启任务。
部分行为需要连接 UU 远程和真实安装虚拟显示器驱动，按下表记录观察结果。

v1.0.5 的验收重点为原版界面融合、搜索控件和预览选屏隔离。桌面截图与自动测试不代表已重新完成真实 UU 触屏验收。

## 0. 先跑静态门禁（不用启动程序）

```powershell
pwsh -File scripts\fetch-driver.ps1
cargo build --release -p snug-app --offline --target-dir target\release-check
pwsh -File scripts\build-release.ps1 -Exe target\release-check\release\snug.exe -ReleasesRepo mirakyux/snug-win-rust
pwsh -File scripts\preflight.ps1 -Exe target\release-check\release\snug.exe -ReleasesRepo mirakyux/snug-win-rust
```

静态检查包括版本、体积、应用清单、系统 DLL 依赖、更新源，以及 `dist` 中的 ZIP 和校验和。
检查结果出现 `SKIP` 时，核对跳过原因。

完成静态检查后再启动 EXE 确认运行行为。第 9 项在 Release 公开后执行。

## 1. UU 开屏不误报，断开后撤屏

先从普通权限启动新 EXE，确认设置显示「普通用户」。驱动管道需要提升权限时，确认 Snug 在启动阶段请求代理授权。授权后连入远控，确认建屏直接使用已准备好的连接。取消授权后连入远控，确认建屏反馈权限问题，再在「通用 → 驱动与日志」点「重试连接」重新授权。驱动安装走固定管理员入口。自动更新在普通权限下执行，受保护目录需手动替换。
默认数据目录启动时会后台迁移旧的最高权限自启任务；由旧任务启动的本次进程仍是高权限，退出后重新普通启动。旧任务拒绝普通用户修改时，可显式管理员重启一次完成迁移。设置 `SNUGWIN_HOME` 的隔离测试实例不会修改全局自启任务。

在拥有管理员权限的登录账户中，以普通权限运行 Snug。在「桌面设置 → 通用 → 偏好」勾选「登录后后台启动」。驱动首次需要授权时，完成一次 UAC 确认。重新登录 Windows，确认 Snug 以普通权限启动并连接驱动，期间无 UAC 提示。升级测试使用已有登录自启、尚未授权驱动的配置。确认后台启动不弹 UAC，手动打开 Snug 可补齐首次授权。取消勾选后重新登录，确认 Snug 不再自启。手动打开 Snug 时仍可使用已经授权的驱动。

先将「手机屏显示」设为「连接时显示」，再检查以下步骤。

| 步骤 | 期望 |
| --- | --- |
| 手机连入 UU | 日志 `远程会话：已连入（控制端 N 个）`，然后 `手机屏 #N 已就绪（W 宽）` |
| 只运行 UU/GameViewer 或本地游戏，无手机远控 | 仅 SLOG 增长时不应记录远程连入或新建虚拟屏 |
| UU 在托盘且使用硬件编码，从电脑或手机连入 | 日志显示视频编码活动及「远程会话：已连入」，「连接时显示」自动建屏 |
| 会话开始时控制端表不可读或为空 | 手机屏保持关闭。需要提前建屏时，可改选「始终显示」 |
| 已确认远程会话进入空闲 | 最近一次控制端证据后的 15 秒内，SLOG 心跳可以维持；超过该窗口需重新出现正向证据 |
| 会话中切到 UU 设置页 | 记录控制端不可读。最近控制端证据后最多 15 秒可由 SLOG 衔接。需要持续留屏时，可改选「始终显示」 |
| 被控页面明确显示空控制表，但 SLOG 仍增长 | 空表优先，按原断开防抖进入重连窗口；不能用本地心跳继续保活或重连 |
| 手机上照常用（开 App、铺窗） | 与之前一致 |
| 已取消权限请求或代理断开时，点「重试连接」 | 能重新连接。仍有开屏请求且建屏已失败时，恢复建屏。建屏重试期间保持原授权状态 |
| 应用分辨率后查看 Windows 显示设置 | 实际宽高与配置一致，刷新率约为 60 Hz；目标模式未确认时显示失败，原配置可重新应用 |
| **手机上退出远控** | 日志 `远程会话：已断开` → 约 15 秒内 `远程会话：本次会话结束，撤掉手机屏` → 显示器列表里那块虚拟屏消失 |
| 撤屏后查看托盘 | 状态不再显示“手机屏：在线”，在线图标恢复为空闲；无需重连、点击主窗口或等待下一次实体屏拓扑变化 |
| 撤屏时界面没有新绘制帧 | 后台清除旧手势接管区域及安装缓存；原生心跳仍持续唤醒，重连相同尺寸时可重新安装钩子 |

断开耗时按日志里的「已断开」「本次会话结束」和虚拟屏实际下线三个时点记录，同时核对撤屏完成后托盘显示「关」。另测一次跨会话快速重连，确认旧窗口操作不会传到新手机屏。

离线时切换到「始终显示」，确认手机屏就绪。连入 UU 并铺窗后断开，确认窗口归位且同一块虚拟屏仍在线。切换「关闭」后确认撤屏。再选「始终显示」并退出 Snug，确认虚拟屏撤掉。重新启动后确认按已保存的方式建屏。

在实体屏上打开「桌面设置 → 屏幕 → 虚拟屏投影」。核对竖屏和横屏画面比例，单击画面中央和靠近边缘的控件，确认虚拟屏对应位置收到左键点击。将虚拟屏放到主屏左侧后重复测试。撤屏后，投影应撤下旧画面并显示离线提示。

如已有 `rizetngan/snug-for-windows` v0.2.47 的捕获监视服务，可在启动 Snug 前用 `$env:SNUG_UU_CAPTURE_FEED = '1'` 启用只读观测。监视命名管道只允许一个客户端，联调前先退出原应用。分别测试正常断开、信号失效、多人会话和切屏导致捕获重建。信号不足时按原 UU 重连窗口处理。 [捕获监视上游](https://github.com/rizetngan/snug-for-windows/tree/v0.2.47/Platforms/Windows)

### CrossDesk 真机远控待验收

在通用设置启用实验性 CrossDesk，用手机端的绝对鼠标模式连入。依次核对桌面端识别会话、手机屏是否可选、左键点按和按住拖动、点击关闭前归位，以及「连接时显示」下断开后撤屏。另测同一 Windows 登录会话下的桌面版重启与观察信号丢失。如果 CrossDesk 需要先发现手机屏，改用「始终显示」，待手机屏就绪后重启 CrossDesk，并核对断开时留屏。

在「连接时显示」下，断开 30 秒后仍能在 Windows 显示设置里看到手机屏，视为撤屏失败。

> 15 秒是 C# 的重连窗口（`EpisodeControllers` 里 `RECONNECT_WINDOW`），不是卡住。
>
> 本项目额外限制：SLOG 不能单独恢复断开的会话，避免本地 GameViewer/游戏心跳把手机屏复活。

## 2. 建屏期间界面不卡

| 步骤 | 期望 |
| --- | --- |
| 手机连入的瞬间，在手机上划界面 | 界面照常响应，最多状态慢一拍（≤0.5 秒），**不出现整块卡死几秒** |
| 日志 | 建屏那几秒里仍在往下写（`资源库：…` 之类），不是一段空白 |

背景：worker 在 `DeskSet` 的锁里跑建屏（最长 8 秒 × 4 候选），界面改成只读快照、写排队。
如果卡死，说明又有人在界面上等那把锁了。

## 7. 桌面预览

| 步骤 | 期望 |
| --- | --- |
| 没连手机时，托盘「预览手机界面…」或运行 `snug.exe --preview` | 主屏中间出现按已配置分辨率比例的界面，显示紧凑的只读预览标记和关闭入口 |
| 点 App、窗口或资源库中的桌面操作 | 不启动、关闭或搬移应用，日志 `预览：只读模式，未执行应用或显示器操作` |
| 关闭预览 | 窗口回到屏幕外待命 |
| 连着手机时点预览 | 不改开预览，而是回到资源库列表 |
| 真实活动屏为 A，预览中选 B，再关闭预览并连入 UU | 真实选择仍为 A，A 建屏后界面正确显示，托盘状态与 A 一致 |
| 真实活动屏为 A，预览中选 B，保持预览时连入 UU | A 就绪时预览自动让位，界面显示 A；预览的临时选择 B 不传给控制器 |
| 主触控屏使用默认选择时重复上述步骤 | 关闭或让位后仍使用默认主屏，界面和控制器选择一致 |

预览的只读限制适用于资源库中的应用与显示器动作。设置页仍可保存真实配置、修改自启或执行驱动等系统操作；检查布局时只浏览设置。

布局检查可使用以下参数：

| 参数 | 页面或输出 |
| --- | --- |
| `--preview` | 运行中资源库 |
| `--preview-all` | 全部应用 |
| `--preview-search=keyword` | 已输入关键词的搜索页 |
| `--preview-settings=screens` | 屏幕设置；也可选 `interaction` 或 `general` |
| `--preview-output=path` | 约 3 秒后通过 egui 帧缓冲保存本视口 PNG，可与页面参数组合；输出目录需已存在 |

隔离截图使用独立的 `SNUGWIN_HOME`，并关闭 `PhoneScreen`、`Gestures`、`AutoCheckUpdates` 及所有 `Screens[].enabled`。仅关闭 `PhoneScreen` 不足以禁用自动建屏，配置同步可能根据启用的屏幕重新打开总开关。截图期间不启用屏幕、不执行设置中的系统动作。

## 9. 手机面板跳转、虚拟屏消失与长稳

以下为待执行场景。每个场景使用独立运行编号；稳定会话试验期间不得并行退出、重启或重建 Snug，以免把受控生命周期动作误判为面板故障。

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 稳定会话中的面板导航 | UU 保持连接，手机屏已就绪；在同一 Snug 进程中交替打开普通 App、返回资源库、切换窗口并返回。每个动作单独打时间标记，至少往返 10 轮。 | 只发生预期的页面切换；Snug PID/start time、当前虚拟屏身份和分辨率保持不变。不得意外退回 App 页、落回主屏或重新启动 Snug。 |
| 面板意外跳回 App 页 | 在上述稳定会话中复现用户报告的跳页。出现时停止操作并保留现场，不先退出、重连或重建。 | 故障本身记录为失败；取得跳转前后页面、屏幕可见状态和进程/显示证据后，才执行单独恢复步骤。不得把随后重启后的默认 App 页算作跳转复现或恢复通过。 |
| 虚拟屏意外消失与恢复 | 稳定显示手机画面时持续观察 Windows 显示列表、Snug 诊断、owner 状态与 CCD。若屏幕消失，记录精确时间和手机画面；之后仅通过产品提供的重试/恢复入口，或在独立运行中重启 Snug，验证恢复。 | 稳定观察期间无未请求的撤屏；发生异常时，恢复后只出现一块本次 owner 拥有的屏，分辨率/刷新率符合配置，物理屏拓扑不变，手机画面及点击恢复。不得用全局 `RemoveAll` 清理。 |
| 连续长稳 | 先确认进程、驱动、模式、DPI 与手机连接稳定，再连续运行至少 30 分钟。固定二进制、配置和 DPI；每 5 分钟检查画面、点击和滚动，资源采样间隔不超过 30 秒。 | 30 分钟内无意外进程重启、面板跳页、虚拟屏丢失、输入失效或未解释错误；手机检查点均通过。记录 private bytes、working set、CPU 的峰值和时间斜率。未预先定义资源上限或观测到持续增长时，只报告观测值，不据此宣称内存平台或长期稳定。 |
| 正常退出和重启 | UU 会话中通过托盘正常退出；等待进程树结束并检查显示拓扑。随后用同一配置重新启动，单独观察建屏与手机画面恢复。 | 30 秒内本次进程树全部退出；只撤销本次 owner 的虚拟屏，物理屏快照与基线一致。重启后只建一块目标屏，无重复屏、孤儿屏或意外清理其他 owner 屏幕。 |

## 2026-11-26 横屏建屏实机失败（合入阻断）

北京时间 2026-11-26 17:00 左右，直接创建控制 `landscape-create-real-root-r1` 以失败状态结束。新驱动 `0.4.0.12`、`ROOT\\DISPLAY\\0001` / `oem72.inf` 已成功装入；测试 owner 创建目标后，驱动 mode list 为 `1920×1080@60`。事件日志中约 0.46 至 15.40 秒的 26 次桌面枚举快照都仍显示该虚拟桌面为 `1080×1920@60`。但验收 harness 随后报告 `Harness exited or timed out before target hold`，正式 CCD 样本数为 0；因此本次没有完成 CCD hold 验证，不能把这些桌面枚举读数描述为 CCD 采样通过或失败。应用与手机交互均未启动（`applicationStarted: false`）。

失败前的诊断快照 `diagnostic-0002-after-create.json` 显示目标时序已为 `1920×1080@60`，CCD source mode 及桌面 bounds 仍为 `1080×1920`，路径旋转为 identity。尺寸不一致不是旋转造成；现有证据将阻塞收敛定位在 Windows 源模式/桌面未采用目标时序，具体驱动或系统原因仍未确定。

失败结果见 `target/expanded-acceptance-20261126/landscape-create-control-r1/runs/landscape-create-real-root-r1/result.json` 与 `runs/landscape-create-real-root-r1/mode-1920-1080-60/events.jsonl`。owner 清理成功，候选驱动回滚到 `0.4.0.1` / `oem17.inf`，进程树退出，原有物理桌面精确核验通过。以上恢复通过不改变横屏功能验收失败的结论。

当前 V2 owned 路径为避免可复用显示身份上的竞态，只进行驱动 owner 保护的模式表更新并等待 Windows 实际模式读回，不执行 GDI/CCD 原生回退。独立代码审查确认，将原生桌面写入简单插回会留下 owner 检查与系统写入之间的竞态；现有 Windows 写入接口不接受 Snug owner 条件。结合本次多次桌面读数仍为竖屏以及 harness 未完成正式 hold，横屏应用级分辨率创建/应用仍未验收通过；不能把早先仅覆盖标准与 phone 模式的 v12 Smoke 通过记录外推到此场景。

**当前合入判定：阻断。**须先有可证明不会写入物理屏或其他 owner 显示器的桌面模式切换方案，并完成并发/身份复用回归和本机横屏实测；不得仅以扩大超时或恢复无保护的原生写入关闭失败。稳定 UU 导航、异常恢复及 30 分钟手机交互场景仍按第 9 节待验收；本次实机未启动应用且当前电脑没有可操作的 UU 窗口，不能记作通过。
