# 本轮真机验收单（v1.3.0 功能面收尾）

重启程序后照着勾。每条都写了**该看到什么日志**，看不到就是没生效。

> 前提：现在跑的是旧进程。要让新构建生效，得**退出再启动**（托盘 → 退出，或数据目录放
> `quit.request`）。新 exe 在退出后才能覆盖，或直接用
> `cargo build --release -p snug-app --offline --target-dir target\release-check` 的产物。

## 0. 先跑静态门禁（不用启动程序）

```powershell
pwsh -File scripts\preflight.ps1 -Exe target\release-check\release\snug.exe
```

它只查「发出去的那个 exe 是不是发布形态」：版本与 `Cargo.toml` 一致、体积在 8 MiB 内、
清单是 `requireAdministrator` + PerMonitorV2 + UTF-8、`dumpbin` 里只有系统 DLL、
dist 的 zip 与 checksums 对得上。**全 PASS 再往下点**；SKIP 的项要看清原因。

它不验证任何行为——下面八组才是行为验收。

## 1. 该撤的屏会撤（本次最重要）

| 步骤 | 期望 |
| --- | --- |
| 手机连入 UU | 日志 `远程会话：已连入（控制端 N 个）`，然后 `手机屏 #N 已就绪（W 宽）` |
| 手机上照常用（开 App、铺窗） | 与之前一致 |
| **手机上退出远控** | 日志 `远程会话：已断开` → 约 15 秒内 `远程会话：本次会话结束，撤掉手机屏` → 显示器列表里那块虚拟屏消失 |

失败判据：断开 30 秒后虚拟屏还在（`Get-CimInstance Win32_DesktopMonitor` 或显示设置里能看到）→ 没生效。

> 15 秒是 C# 的重连窗口（`EpisodeControllers` 里 `RECONNECT_WINDOW`），不是卡住。

## 2. 建屏期间界面不卡

| 步骤 | 期望 |
| --- | --- |
| 手机连入的瞬间，在手机上划界面 | 界面照常响应，最多状态慢一拍（≤0.5 秒），**不出现整块卡死几秒** |
| 日志 | 建屏那几秒里仍在往下写（`资源库：…` 之类），不是一段空白 |

背景：worker 在 `DeskSet` 的锁里跑建屏（最长 8 秒 × 4 候选），界面改成只读快照、写排队。
如果卡死，说明又有人在界面上等那把锁了。

## 3. 主题

| 步骤 | 期望 |
| --- | --- |
| 设置 → 首页「外观」→ 点「暗黑」 | 界面立刻变深色，日志 `主题：Dark（深色）` |
| 点「浅色」 | 立刻变浅色，文字不再是浅灰配浅底 |
| 点「自动」 | 跟随 Windows「个性化 → 颜色 → 应用模式」；改系统设置后几秒内界面跟着变 |
| 关掉设置再开 | 主题还是刚才选的（写进 config.json 的 `Theme`） |

## 4. 控制中心式设置

| 步骤 | 期望 |
| --- | --- |
| 托盘双击 | 打开设置，落在**首页**（四张卡：状态 / 当前手机屏 / 外观 / 细项） |
| 首页「当前手机屏」 | 机型名 + `宽 × 高 · 200%` + 字号 −/+ 能改档位 + 预览界面 + 换机型 |
| 点「换机型…」 | 跳到「多屏与设备」页并展开机型列表（可搜索） |
| 托盘「检查更新…」 | 打开设置并停在**关于与更新**页 |
| 五个页签都能进 | 控制中心 / 手势与交互 / 驱动与日志 / 关于与更新 / 多屏与设备 |

## 5. 多屏与设备

| 步骤 | 期望 |
| --- | --- |
| 多屏页 | 列出当前屏（名称、`手机 · 竖屏` 徽标、规格、启用、预览、换机型、删除） |
| 添加一块平板 | 列表多一项，`多屏 2/4` |
| 连上手机 | **只建一块**虚拟屏（当前选中的那块），不会多出黑屏 |
| 界面上点另一块屏的名字 | 日志 `切换屏幕：…`，旧屏撤、新屏建，界面跟过去 |
| 删除第二块屏 | 列表只剩一项，`多屏 1/4` |
| 加到 5 块 | 「选型号并添加」变灰，提示"已经到上限 4 块" |

## 6. 重入胶囊

| 步骤 | 期望 |
| --- | --- |
| 手机连入后，点界面右上角「⏏」 | 弹出确认条「退出手机屏？」，有「退出」「稍后」 |
| 点「稍后」 | 确认条收起，什么都不变 |
| 再点「⏏」→「退出」 | 日志 `界面：确认退出手机屏` + `收起手机屏：<id>`；铺着的窗口还回原位；电脑屏幕右下角出现胶囊「📱 进入手机屏 ×」 |
| 点「进入手机屏」 | 屏建回来，界面回到手机屏，日志 `重入胶囊：进入手机屏` + `重新进入手机屏` |
| 再收起，点胶囊的「×」 | 胶囊消失，日志 `重入胶囊：用户收起`；托盘「重新进入手机屏」仍可点 |
| 断开远控 | 胶囊也跟着消失（不在会话里了） |

## 7. 桌面预览

| 步骤 | 期望 |
| --- | --- |
| 没连手机时，托盘「预览手机界面…」 | 主屏中间出现按机型比例的手机界面，顶部`预览模式 · 只读（xx%）`横幅 + 「关闭预览」 |
| 点任意 App | 不执行，日志 `预览：只读模式，忽略这次操作` |
| 点「关闭预览」 | 窗口回到屏幕外待命 |
| 连着手机时点预览 | 不改开预览，而是回到资源库列表 |

## 8. 退出与残留

| 步骤 | 期望 |
| --- | --- |
| 托盘 → 退出 | 30 秒内进程退出（`Get-Process snug` 为空），虚拟屏全部撤销 |
| 退出后再启动 | 日志里**不会**出现"清理残留手机屏"（没有残留）；如果出现过，说明上次没撤干净 |
| 强杀进程后重启 | 日志 `已按归属记录清理残留手机屏：#N`，只清自己建的，不动 C# 版建的屏 |

## 已知不做的（不是 bug）

- **多屏不是同时 4 块**：同一时刻只建当前选中那块（见 `multi-screen.md`）。
- **计划任务/开机自启**不在本轮范围。
- 托盘右键菜单的实际点选没法用脚本验证（DPI 虚拟化导致 SendInput 偏坐标），只能手点。
