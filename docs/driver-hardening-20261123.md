# 虚拟屏驱动集成与可靠性改进

## 范围与顺序

本轮落实驱动评估中确认的不足，并在 README 直接说明 `MolotovCherry/virtual-display-rs` 的来源、作用和构建方式。

1. 用失败回归保护显示模式的实际读回、超时和错误返回，再修正建屏、分辨率应用和模式恢复。保留精确分辨率、不自动扩屏、仅管理归属屏的边界。
2. 区分代理启动取消与运行途中断线，提供显式重新连接；保留固定管理员入口、双向身份校验与有界等待。
3. 补充实际驱动版本、设备问题码和管道权限诊断，避免把内嵌安装包版本当成系统实际版本。
4. 将上游源码固定到可追溯提交，独立于 GUI 工作区构建。修复 swapchain 设备与表面的 COM 引用释放，保留 IPC、模式与帧调度语义；保留对应许可证。
5. 提供驱动构建、ABI 检查、签名、打包和产物校验流程；仅将验证过的驱动包接入发行构建。驱动签名、系统安装与源码编译分别记录结果。
6. 更新 README、第三方声明、安装/更新说明及验收单，明确当前使用的二进制与源码版本。

## 验收

- 显示器上线与实际宽高、刷新率均符合目标，才报告成功；模式超时和 Win32 失败保留可重试状态。
- 修改失败不丢失已有屏的归属，不操作不属于 Snug 的显示器；恢复模式根据已绑定身份定位。
- UAC 取消不触发后台反复请求；用户显式重试可恢复连接，代理死亡或 I/O 超时有明确诊断。
- 驱动源码、许可证、上游提交与补丁均可追溯；获取的帧表面仅在成功、非空时接管并恰好释放一次。
- Debug / Release 测试、正确性 Clippy、应用构建和发行包预检通过；驱动使用锁定依赖单独构建并核对 WDK ABI。
- 真实驱动验收记录加载的 DLL 哈希、系统实际模式、建撤屏循环和空闲后的资源情况。源码检查或成功编译不替代实际加载后的验证。

## 实施边界

不向用户电脑导入来源不明的私钥，不复用上游私钥。签名产物需使用可控的证书；真实替换前保留现有包及回滚方法。自动测试使用隔离夹具；驱动安装和显示拓扑实验另行记录，不与回归测试混为一谈。

## 验证结果

- 驱动 `0.4.0.1` 使用上游锁定的 Rust nightly、Windows SDK `10.0.26100.0`、WDK `10.0.26100.6584`、LLVM `18.1.3` 完成 x64 Release 构建。14 项 swapchain 布局一致，Inf2Cat 生成目录文件时报告 0 错误、0 警告。驱动和许可证一起写入独立 ZIP。
- 应用 Debug、Release 各通过 645 项测试。每种配置有 1 项需管理员令牌的 staging ACL 测试按既有门禁设置跳过。两种配置的 Clippy correctness、suspicious 门禁通过，应用 Release 构建及 18 项打包预检通过。
- 本机只读诊断读到已安装的 PnP 版本 `0.3.0.0`，设备已启动，普通权限打开驱动管道返回 5。CCD 现有拓扑验证返回 0。探测未发驱动命令，也未改变显示拓扑。
- 普通权限连接先尝试直接访问，只有管道访问被拒绝时才走受限代理。双向协议的 `Notify` 会替换整张列表，Snug 先读取状态并保留其他条目。建屏会拒绝已占用的编号。若其他客户端在读写之间同时更改列表，上游协议没有原子更新功能。
- `0.4.0.1` 已生成未签名构建和自签名测试包。测试包尚未加载，长时间资源占用、睡眠唤醒和 UU 手机联调也待验收。发行签名和真机验收完成前，Snug 的常规构建和发布继续使用上游 `v0.3.1` 安装包。
