# 崩溃恢复与权限验收补修计划

本轮处理上一轮仍保留的实际风险。保留工作区已有修改，不增加依赖，不提交或推送。

## 跨屏转移

1. 先用故障回归锁定来源记录移交时的持久化空窗。
2. 目标屏先完成原有恢复，来源记录再原子移动到目标记录路径。移交前后只保留一份权威记录，避免先删除来源再写目标。
3. 移交失败保留来源；目标接收后失败由目标恢复，不复活旧来源。

## 字号操作

1. 区分未发送、完整发送和部分发送后不确定三种结果。旧布尔失败不能证明零步生效。
2. 原生操作前持久化单个执行意图；操作后先保存权威记录，再清理意图。
3. 崩溃或部分执行后保留意图，暂停自动消费和偿还，提供明确提示及用户手动还原后的确认入口。相对快捷键没有幂等或绝对字号查询，不凭日志猜测已执行步数。
4. 用中断、保存失败、重启和重试测试证明不会重复发送或悄悄删除债务。

## 显示归属竞态

并行核查带目标身份的系统 API 与驱动锁的可行边界。方案必须覆盖真正的写入过程；额外查询或后验检查不能算作原子授权。实现前记录功能影响，保留失败状态和恢复凭据。

## 权限与硬件验收

实际执行当前令牌允许的 ACL 和符号链接测试，读取现有驱动版本及签名条件。需要提权、开启测试签名或切换真实驱动时记录准确阻断，不修改系统安全设置或真实显示拓扑。

## 验收

先专项红绿，再运行工作区 Debug、Release、Clippy 和发布构建。驱动代码若改变，重跑受影响专项并构建当前候选。独立复核新增边界，完整记录实测与未测部分。
