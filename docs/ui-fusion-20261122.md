# v1.0.5 界面融合与发版记录

发版日期：2026-11-23。本文保留 2026-11-22 开始的界面融合方案，并记录后续修正与验证边界。

## 目标与边界

用户要求结合 macOS 原版 README / UI 与现有 Rust 版本，并确认设置页也一起精简。

本次参考原版 `main` 快照：`df92410dfe78511b15db2bc9b657b1c845c0aa82`。已阅读全文、设计原则和原型，直接检查 14 张 README 截图，抽查 19.35 秒演示的 8 个画面，并交叉阅读 SwiftUI 实现。

视觉以用户提供的运行中、全部、搜索三联图为准。原版源码用于核对行为，不能用结构相似代替截图中的控件比例、间距和层级。Windows 独有功能通过屏幕菜单与三类设置提供。

保留现有 Windows 驱动、窗口处理、手动精确分辨率、性能优化、断开撤屏与原生心跳。此次融合不改为按机型计算分辨率，也不加入自动扩屏、常驻系统主屏或多块虚拟屏同时创建。

## 实施顺序

1. 先用回归保护原有导航、危险操作确认、设置应用边界和窄屏布局。
2. 触控资源库默认进入运行中：当前 App 优先，App 卡片直接显示窗口行；全部应用保留网格；横屏使用 App / 窗口双栏；搜索匹配应用与窗口。
3. 按用户提供的三张图对齐视觉：顶部左侧返回当前 App 胶囊，右侧小屏幕图标；设置、切屏、收屏功能放进该图标菜单。搜索使用灰底无框，运行中 / 全部使用共享分段轨道；App 卡片使用紧凑行和圆形小图标操作。去掉资源库底部常驻三项导航，使用窗口时保留轻量返回资源库栏和可选截图。
4. 设置归为屏幕、交互、通用。屏幕列表采用短行，进入详情后编辑分辨率；添加屏幕单独展开。删除需要确认。通用收纳外观、自启、更新、驱动和日志，保留现有动作入口。
5. 复用现有控件、颜色、图标缓存和控制器动作，移除旧资源库与设置中被替代的重复入口，不增加依赖。
6. 验证关键按钮、资源库预览限制、横竖屏、长标题、浅深色和窄屏；运行 Debug / Release 测试、Clippy、构建及打包检查，在隔离预览中截图核对实际渲染。

## 验证重点

- 选择窗口、返回资源库和返回当前 App 不改变固定分辨率。
- 关闭窗口、退出 App、删除屏幕第一次点击均不执行危险动作；确认才执行。
- 搜索能找到应用及窗口；布局切换不保留已经失效的窗口选择或确认状态。
- 窄屏和横屏不横向溢出，操作按钮可触达；长标题截断，主操作不被挤走。
- 分辨率预设、恢复默认和自定义仍只改草稿，点击应用才生效；驱动修复、日志、更新及自启入口保留。
- 预览临时切换到 B，不改变真实活动屏 A；关闭预览或真实手机屏就绪让位后，界面与控制器仍选择 A。默认主屏选择也遵循同一规则。
- 资源库预览拦截启动、关闭、搬窗及显示器动作。设置页仍操作真实配置和系统，隔离截图时只浏览设置，不测试驱动、自启或真实应用动作。
- 真实截图只证明渲染结果；测试夹具不启动、关闭、搬移用户的实际应用，不发送外部测试消息。

本轮范围为 v1.0.5：完成界面融合与验证后提交、推送并发布新版。发布提交与资产信息在最终检查后记录。

## 第一轮纠偏

用户指出第一轮预览与所给原图无关。原因是只采用卡片/双栏结构，却保留了原有大文字按钮和偏松的比例。后续以用户图的视觉比例为准，收紧导航与卡片；Windows 的功能和分辨率策略通过菜单与设置提供。

每轮修改后先检查实际程序截图，再决定是否继续调整。比较运行中、全部和搜索页面的导航、搜索框、分段轨道、卡片及网格尺寸，并检查横屏与浅深色。布局测试只能证明交互和边界，不能单独证明视觉已对齐。

## 搜索控件修正

用户继续指出搜索灰底不明显、顶部比例偏松。原实现对颜色调用 `gamma_multiply`，同时缩小预乘 RGB 和 alpha；叠在同色页面底色上后，搜索填充几乎消失。搜索框和分段轨道改用不透明 RGB 灰色，并收紧顶部间距。

搜索编辑框的 `Ui::put` 曾回退外层横向布局游标，导致右侧取消按钮与清除按钮重叠。现在用 `Ui::place` 在预分配区域绘制编辑框，并增加窄屏下清除、取消区域分离及点击行为的回归检查。

## 截图方法

实际渲染截图改用 egui 官方 `ViewportCommand::Screenshot` 与 `Event::Screenshot` 读取本视口帧缓冲，不依赖窗口是否被其他窗口遮挡。`--preview-output=path` 约 3 秒后请求截图并写入 PNG；输出目录需事先存在。

`--preview-all` 直接打开全部应用，`--preview-search=keyword` 打开搜索页，`--preview-settings=screens|interaction|general` 打开对应设置页。这些参数可与截图输出组合，用于复查同一版本的布局。

隔离截图使用独立 `SNUGWIN_HOME`，并将 `PhoneScreen`、`Gestures`、`AutoCheckUpdates` 和所有 `Screens[].enabled` 设为关闭。否则 `sync_legacy` 可能根据启用的屏幕恢复自动开屏总开关。截图只浏览界面，不操作真实应用、驱动或全局自启任务。

布局场景包括竖屏运行中、全部、搜索、深色资源库、横屏资源库，三类竖屏设置及深色横屏设置，共 9 个场景。截图保存在本地 `target/ui-fusion-20261122/`；最终搜索修正后已重新生成，灰底和清除、取消的分离已从实际帧缓冲截图核对。
