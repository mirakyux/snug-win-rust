# 底栏无响应、撤屏残留与面板消失修复

## 证据与原因

2026-11-22 13:59:06，QQ 铺入手机屏后，后台串行队列的慢动作日志向已关闭的 stderr 管道写入，触发 panic。界面线程继续刷新，但队列无法再执行按钮和撤屏动作。14:01:36 会话结束后，界面按状态移出屏幕，实际虚拟屏因队列失效而残留。

另外，撤屏实现曾在确认下线前移除内存映射和磁盘归属；屏愿望消失后，尚未完成善后的 core 也会被丢弃。窗口摆放还存在忽略 SetWindowPos 错误、只核对尺寸而不核对可见性和置顶状态的问题。

用户确认面板消失时手机仍能操作电脑。14:01 这一段日志只能证明 UIA 证据丢失触发会话超时，不能证明真实断开。此次没有放宽远控准入，也没有让本地推流日志无限保留会话。

## 修改

- `desk/lane.rs`：诊断写入失败不再使队列崩溃。
- `desk/engine.rs`、`desk/set.rs`、`desk/test_support.rs`：保留撤屏善后状态，5 秒限频重试，屏愿望移除后也继续推进；同一活跃 desk 重入先等待旧屏下线。
- `display.rs`：保留映射和归属，确认实际下线后销账；启动清理只释放确认离线的编号。
- `controller.rs`：2 秒心跳推进善后；启动清理移到后台，仍先于首次建屏；记录列表显示和回到当前窗口请求。
- `placement.rs`、`lib.rs`、`ui.rs`：核对窗口可见性、置顶和输入样式；真实 Win32 失败返回失败，面板可重新摆放；记录底栏点击坐标与控件区域。
- 根版本与锁文件更新为 1.0.3；没有新增依赖。

保留现有串行队列、归属账本和摆放请求，未引入新的后台服务或显示器接管机制。
